# Spark 轮足机器人实验平台：当前实现盘点与真机对接方案

> 盘点日期：2026-09-29  
> 依据：本工作区 `web/`、`server/` 实际源码及一次前端生产构建。本文记录**代码现状**和**下一步实施方案**；接口与硬件设计细节仍参见[最终开发说明](Spark轮足机器人实验平台_最终开发说明.md)。没有连接 Spark 实机，因此任何硬件运行状态都尚未经过本次验证。

## 1. 一句话结论

当前项目已搭建 **Web 演示平台**：前端已通过生产构建，账号注册、登录、资料和密码修改的代码已接入 FastAPI 与 SQLite；机器人相关 REST/WebSocket 接口主要返回固定或进程内演示数据；页面外观基本齐全，但导航、遥控、巡检、语音执行、视频等功能尚未形成真机闭环。仓库内没有 `spark_web_platform/` ROS 适配工程，也没有已验证的真机联调记录。

阅读页面时要区分四种状态：

| 状态 | 含义 | 当前例子 |
|---|---|---|
| 已实现并持久化 | 请求到后端，结果写入 SQLite | 注册、改资料、改密码、账号操作日志 |
| 已有接口但仍是演示 | 前后端可通信，返回值不是实机采集 | 机器人状态、连接测试、能力、语音记录、巡检任务列表 |
| 仅进程内状态 | 后端重启即丢失，不触发机器人动作 | 点位增删改查、导航状态、急停标志、控制租约 |
| 仅页面展示或局部交互 | 页面可看、部分按钮改变本地状态，但未调用业务接口 | 地图导航按钮、遥控方向键、巡检操作、视觉与日志页面 |

**注意**：顶栏的“实时已连接”目前表示浏览器连上了 FastAPI 的演示 WebSocket，不表示 Spark 真机在线。演示状态中 `online: true`、IP、CPU、位姿、速度和传感器状态来自写死的样例快照。

## 2. 仓库与运行方式

```text
spark/
├── README.md                 项目启动说明
├── docs/                     设计契约、本盘点
├── UI/                       八张页面参考图
├── web/                      React 19 + TypeScript + Vite 8 + Tailwind CSS 4
│   └── src/
│       ├── api/              HTTP、WebSocket、请求类型
│       ├── store/            账号与机器人全局状态
│       ├── mock/             浏览器内置演示数据
│       ├── pages/            业务页面
│       └── components/       页面布局、总览卡片、基础控件
└── server/                   FastAPI + SQLAlchemy + SQLite
    ├── app/                  入口、配置、ORM、校验、鉴权、路由
    └── data/spark.db         本地开发数据库
```

启动步骤见根目录 `README.md`：后端默认 `127.0.0.1:8010`，前端为 Vite 开发端口；前端默认把 `/api/v1` 和 `/ws/v1` 指向本机后端。`VITE_API_BASE_URL`、`VITE_WS_BASE_URL` 可覆盖地址，`VITE_USE_MOCK_API=true` 可强制浏览器使用内置机器人演示数据。当前只有一个固定机器人 ID：`spark-01`。

后端环境变量在 `server/app/config.py`：`SPARK_DATABASE_URL`、`SPARK_JWT_SECRET`、`SPARK_TOKEN_TTL_MINUTES`、`SPARK_CORS_ORIGINS` 等。默认 JWT 密钥和演示账号只适合本地开发；正式部署必须替换。当前启动会自动创建演示账号。

## 3. 已实现功能：按页面说明

| 页面 | 现在确实能做什么 | 数据/操作边界 |
|---|---|---|
| 登录、注册、个人资料 | 表单校验；注册、登录、获取当前用户、改资料、改密码；JWT 会话；后端记录账号操作日志 | 页面显示取自数据库。`/auth/me` 允许用户提交自己的 `role`，正式使用前必须修正权限逻辑。个人资料页有“仅保存在本机浏览器”的旧提示，与实际实现不符。 |
| 总览控制台 | 展示机器人状态、静态地图、视频占位、语音记录和近期活动；快捷按钮有本地反馈 | 状态来自演示后端或浏览器 Mock；近期活动始终是浏览器 Mock；快捷导航和急停未调用后端。 |
| 机器人管理 | 展示状态中的系统资源、电源占位和机器人信息 | 页面未调用机器人列表、能力或连接测试 API；传感器行、MAC、ROSBridge 地址、部分系统信息固定写在页面。连接测试按钮未接线。 |
| 地图导航 | 展示静态 SVG 地图、位姿字段、演示点位；点位搜索与选择有本地交互 | 后端 `/map` 明确返回 `available:false`、`data:null`；页面直接使用 `MOCK_WAYPOINTS`，导航、取消、保存点位等按钮未调用 API。 |
| 手动遥控 | 方向盘按下高亮；滑块和预设速度调整本地数值；展示状态字段 | 无按键/手柄控制处理、无控制 WebSocket 客户端、无租约请求；页面急停按钮未调用 API。页面关于“松手/失焦/超时自动发送零速度”的文字目前只是目标行为。 |
| 语音交互 | 显示后端语音记录或回退演示记录；“开始识别”切换本地视觉状态 | 没有麦克风采集、机器人语音启停、`/voice/stt` 订阅或语音命令执行。页面“大模型理解”等流程文字是设计展示，尚无相应代码。 |
| 巡检任务 | 显示固定统计、任务、路线、检查项和告警；少量数据引用状态快照 | 后端仅有固定任务列表 GET；页面没有调用它，也没有创建、启动、暂停、恢复、取消任务的实现。 |
| 视觉中心 | 多画面、检测框、统计的页面预览 | 全部为演示内容，无真实视频和检测服务。仓库硬件基线只确认一台 D435，不能把页面四画面当作四路实物摄像头。 |
| 任务与日志 | 任务、告警、报告、操作日志表格的页面预览 | 后端虽把账号操作写入 `operation_logs`，但没有供该页读取的日志 API；页面表格是固定数组。 |
| 系统设置 | 设置分区切换、开关和保存反馈 | 设置未落库，也不影响后端或机器人。 |

前端路由与登录守卫在 `web/src/App.tsx`；请求封装在 `web/src/api/client.ts`；账号会话在 `web/src/store/auth.ts`；机器人状态在 `web/src/store/robot.ts`。机器人状态优先接受 WebSocket 全量/增量事件，也可经 REST 刷新，REST 失败时回退浏览器 Mock。当前 `source: 'live'` 只代表拿到了后端响应，**没有证明是真机数据**。

## 4. 后端接口与存储现状

### 4.1 账号：已经接数据库

`/api/v1/auth/register`、`/login`、`/me`（GET/PATCH）、`/password`（POST）已实现。用户和账号操作日志分别在 SQLite 的 `users`、`operation_logs` 表；密码用 PBKDF2 加盐哈希，登录签发 HS256 JWT。REST 通过 Bearer token 鉴权，WebSocket 握手通过 `?token=` 校验令牌。统一错误信封为 `{"error":{"code","message","details"}}`。

正式部署前需要修正：用户目前可在自己的资料请求中修改角色为 `teacher` 或 `admin`；WebSocket 校验令牌后未再核对用户记录和机器人 ID；令牌放在 WebSocket URL 查询参数中需要考虑日志泄露与短期凭证策略；生产 JWT 密钥、演示账号和跨域白名单需要独立配置。

### 4.2 机器人：接口存在，真实适配缺席

| 接口组 | 已写代码 | 当前返回/处理 |
|---|---|---|
| `GET /robots`、`/{id}`、`/{id}/status`、`/{id}/capabilities` | 是 | 单机固定样例；状态和能力不是实机探测。 |
| `POST /{id}/connection/test` | 是 | 固定返回可达、ROSBridge/ROS Master 正常，不执行网络探测。 |
| `GET /{id}/map` | 是 | 地图不可用、无栅格数据。 |
| 点位 GET/POST/PATCH/DELETE | 是 | Python 列表 `WAYPOINTS`；重启丢失，写入参数缺少正式模型校验。 |
| 导航目标 POST、状态 GET、取消 DELETE | 是 | 修改进程内 `STATE`，不调用 `move_base`。 |
| 控制租约 POST | 是 | 覆盖进程内租约并返回 `expiresIn:15`；无持有人校验、冲突处理、续约或真实到期逻辑。 |
| 急停/复位 POST | 是 | 修改进程内布尔值；没有向底盘发送零速度或执行硬件安全流程；复位尚无教师/管理员限制。 |
| 语音记录 GET、巡检任务 GET | 是 | 固定演示记录/任务。 |
| `/ws/v1/robots/{id}` | 是 | 每约 2 秒推送一次固定状态快照；无 ROS 事件。 |
| `/ws/v1/robots/{id}/control` | 是 | `teleop.velocity` 返回 `SAFETY_GATE_NOT_PASSED`；`teleop.stop` 仅回执，不操作底盘。 |

健康检查 `/api/v1/health` 只确认 FastAPI 自身运行，不代表 ROS 或真机健康。现有数据库没有机器人、点位、任务、地图、事件、语音记录和设置等业务表。`server/app/routers/robots.py` 是当前演示机器人数据与控制占位的集中位置。

## 5. 现状中的重点风险与修正优先级

1. **先修真实/演示标识**：后端演示数据会被前端标作 `live`；“在线”“实时”“30 FPS”“手柄已连接”等固定 UI 文案可能误导操作人员。所有机器人数据应带 `source`、采集时间和过期状态；未接入时明确显示演示或未知。
2. **阻止权限提升**：`PATCH /auth/me` 不应允许普通用户写自己的角色。急停复位、导航、遥控、设置修改应按角色授权并记录操作者。
3. **运动控制保持关闭**：当前前端未实际下发速度，但后端导航会返回 accepted，容易误认为已执行。真机安全门禁通过之前，明确返回“演示/未开放”或保持禁用，并避免页面显示成功执行。
4. **去除假设备状态**：机器人管理和遥控页里的固定传感器、网络、ROSBridge、手柄状态应改为来源可追踪的实时值或 `--`。
5. **补齐服务端边界**：点位与任务改为严格请求模型、数据库持久化；租约需绑定用户、机器人和到期时间；WebSocket 需验证机器人 ID、会话和事件顺序；断连需标记离线。
6. **改正文案与旧文档**：个人资料页和现有“最终开发说明”仍有代码实现前的叙述。阅读本盘点判断现状，阅读最终开发说明判断目标契约。

## 6. 真机对接目标架构

```text
Windows 浏览器 / 机器人触控屏
          │ HTTPS + WebSocket
          ▼
React 页面 → 统一 API 客户端 → FastAPI
                              │ 鉴权、状态聚合、业务任务、日志、租约、限速
                              ▼
                    RobotAdapter 接口
                       ├─ MockRobotAdapter（开发/演示）
                       └─ RosRobotAdapter（Ubuntu 真机）
                              │ 本机 ROSBridge/ROS1 接口
                              ▼
                    spark_web_platform（新建）
                    Topic/TF 映射、状态采集、导航 Action、语音适配、Watchdog
                              ▼
                    Spark ROS1 Noetic 驱动、底盘、雷达、D435、语音
```

保留 `/api/v1` 与 `/ws/v1` 对浏览器的稳定契约。浏览器不直连 `/cmd_vel`，不把 ROSBridge 暴露公网；真机运动控制还需要认证和进程/网络隔离，不能仅靠 ROSBridge 监听 `127.0.0.1`，因为机器人触控屏浏览器也可能在同机访问它。真实数据只在适配层转换；未知或超时字段返回 `null/unknown`，不拿历史快照充实时值。ROS 原始 Topic、消息类型、TF 和设备路径集中配置，而不是散在 React 页面。具体边界见[机器人端实施说明](Spark机器人端ROS1开发与部署实施说明.md)。

## 7. 推荐开发顺序与每阶段交付

### 阶段 0：真机只读核对与安全基线

在 Spark Ubuntu 上确认当前 IP、ROS Master、实际 `rostopic list/type/echo`、`/map`、定位 TF、`/odom`、`/scan`、D435 图像、`/voice/stt` 消息定义、电池输出、底盘及雷达设备稳定路径。记录每一项的**实际 Topic、消息类型、频率、空值/断线表现**。同时确认硬件急停、可用场地、最大速度和谁能复位。现有文档给出的 Topic 是候选映射，不能直接当作已验证值。

**交付**：真机采集表、`topic_mapping.yaml` 的已核实版本、网络拓扑与硬件急停操作记录。没有这些结果时不进入真实运动开发。逐文件机器人侧操作和代码模板见[机器人端 ROS1 开发与部署实施说明](Spark机器人端ROS1开发与部署实施说明.md)。

### 阶段 1：让前后端正确区分演示和真机

在后端引入 `RobotAdapter` 抽象和 Mock/ROS 两个实现，统一状态对象增加来源、采集时间、有效期与连接状态。WebSocket 推送真实采样变化并处理断线；前端在顶栏、卡片和详情明确显示“演示后端”“真机在线”“数据过期/离线”。删除或改成未知值的固定在线、帧率、手柄、ROSBridge 文案。优先接通状态、系统资源、传感器、位姿、实际速度和电池可用性。

**验收**：拔网线/停 ROS 节点后，页面在约定超时内变离线，数据不再被标为实时；Mock 模式仍可演示但来源醒目；无电池来源时仍显示 `--`。

### 阶段 2：地图、视频、点位和页面数据闭环

ROS `OccupancyGrid` 转为 `/map` 及元数据；浏览器渲染实际地图、位姿、路径与目标。D435 RGB 通过受限视频服务提供流，显示真实连接和帧率；首期按一台 D435 设计。点位建立数据库表，与地图 ID/坐标系绑定；导航页改用点位 API。机器人管理页调用能力和真实连接测试；巡检页先读取持久化任务列表；日志页面读取真正的账号操作日志。

**验收**：刷新或重启服务后点位仍在；换地图时不误用旧坐标；视频断流有明确提示；页面不再展示固定成功样例。

### 阶段 3：语音转写双端同步

在机器人端订阅已确认的 `/voice/stt`，将最终/中间结果转换成统一 `voice.transcript` 事件；存储最终文本和执行状态，并同步给机器人屏幕与 Web。重连时按事件 ID 去重并补历史。网页“开始识别”要明确是机器人端语音还是浏览器麦克风，分别设计权限和触发方式；首期先完成转写与查看，命令执行后续走统一任务入口。

**验收**：机器人说话后两端看到同一条最终转写；重复事件不生成重复任务；断网恢复不会重放旧语音命令。

### 阶段 4：安全门禁后开放导航、遥控和巡检

先实现并实测角色权限、单持有者控制租约、续约/到期、速度/角速度上限、导航状态与取消、软件急停、机器人端独立 Watchdog。遥控需连续心跳；松手、窗口失焦、切页、WebSocket 断开、租约过期、服务端故障和急停都要由**机器人端**收敛为零速度。正式导航使用 `move_base` Action，得到目标接受、执行、成功、失败、取消的真实结果。巡检以持久化状态机串联点位、导航、检查与报告，不直接在页面拼接 ROS 命令。

**验收**：先用不接底盘的仿真/空载输出验证所有失联停车路径，再在有硬件急停监护的场地低速测试；未持有租约、急停中或状态未知时命令被拒绝并记录原因。安全测试未通过前保持真机运动关闭。

### 阶段 5：第二期业务

按真实硬件能力实现视觉检测、事件告警、日志/报告、设置持久化和机械臂；一台 D435 的 RGB/Depth 不等于四路实体相机。视觉模型先做轻量化或外部推理评估。设置的安全参数必须由后端和机器人端实际执行，不能只保存 UI 值。
